# Build scripts

All scripts resolve the repository from their own location and support paths containing spaces. They use the local `.dotnet/` SDK when present, keep transient CLI/NuGet data under ignored `.tools/`, and write release output under ignored `artifacts/`.

Run `restore.sh`, `check-workflows.sh`, `check-packaging.sh`, `check-format.sh`, `build.sh`, and `test.sh` for normal verification. `check-workflows.sh` uses actionlint 1.7.12 and verifies the official Linux binary checksum when it must download the tool. `publish-linux.sh` and `publish-windows.sh` create genuine self-contained, untrimmed single-file executables from one Linux machine. `check-linux-native-dependencies.sh` checks the Linux ELF apphost with `ldd`; `smoke-test.sh` launches the executable under Xvfb so embedded Skia and other native libraries are actually extracted and loaded. `package.sh` enforces one output file per runtime and verifies Linux ELF and Windows PE x86-64 formats.

`prepare-release.sh` takes `X.Y.Z` or `patch`/`minor`/`major`, refuses any version that is not new and higher or that already has a tag, moves the `## Unreleased` changelog entries under a dated heading for the new version, sets `Directory.Build.props`, and prints the resolved version. It only edits those two files; committing, tagging, and publishing belong to the `Release` workflow or the manual procedure in `docs/PACKAGING.md`. `prepare-release-assets.sh` copies only the two executables to an empty output directory and gives them versioned release names. `build-arch-package.sh` and `build-rpm-package.sh` consume the executable-only Linux publish directory, then stage the repository licenses and documentation into their distro payloads. The validation and immutable Gitea publication helpers are described in `docs/PACKAGING.md`.

`ci.sh` is the single application CI entry point used by both GitHub Actions and Gitea Actions. Its system prerequisites on a Debian/Ubuntu runner are the .NET 10 SDK, Xvfb, `file`, desktop-file-utils, libxml2-utils, ShellCheck, and the listed Avalonia/Skia runtime packages. ZIP tools are not used. Gitea containers may set `ACTIONLINT_OFFLINE=true` because workflow YAML was already checked before mirroring and a release must not depend on GitHub remaining reachable.
